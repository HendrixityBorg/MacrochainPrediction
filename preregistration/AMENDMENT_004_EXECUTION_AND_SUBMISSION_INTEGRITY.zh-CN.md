# Amendment 004：执行与提交一致性修订

冻结时点：2026-09-04 NFP 官方结果发布前。

## 触发原因

人工提交审计发现最终 NFP A003 的书面 `decision_rule.break_even_probability=0.26`，但冻结执行代码按

```text
tau = (failure_loss + transaction_cost) / (success_gain + failure_loss)
    = (0.25 + 0.01) / (1.00 + 0.25)
    = 0.208
```

产生停止和交易判断。A003 因而不能作为最终演示；它必须保留并标记撤回，禁止覆盖。

同一审计还发现：原输出虽然为三个前缀分别计算停止状态，却把最后一跳写成 ledger 的最终停止结果，
没有明确区分“实际已经停止”与“停止后的反事实诊断”；CI 来源分解也只在终链输出。GitHub 干净提交包
还必须验证官方原始输入可用、中文报告可生成和测试脚本可通过。

## 允许的修订

1. 由执行代码唯一计算 `tau=0.208`，并在 precommit 阶段拒绝书面规则与代码不一致；
2. 新建 A004，固定 `break_even_probability=0.208`，撤回 A003，并重新取得独立时间戳；
3. 将首个非 `CONTINUE` 判断记录为 `execution_stop`，后续前缀标记为
   `counterfactual_after_stop`；仍输出三跳，满足审计需要；
4. 为每个前缀输出参数、测量误差、制度漂移、共同 frailty 和外部截断的方差来源比；
5. 真实封存后自动生成中文运行记录，并把实时 actual、p_i/n_i、CI、停止、决策和哈希写入总报告；
6. 将可再分发的 Philadelphia Fed、Federal Reserve 与 ALFRED 官方原始文件纳入提交，继续排除
   Yahoo 原始长历史；用干净 Git 克隆验证离线运行和测试；
7. 中文化提交入口和数据声明，使用真正的固定依赖文件。

## 禁止的修订

- 不改变 164 条确认链、主标签、开发/确认边界或任何 outcome；
- 不改变三个 `p_i`、`n_i` 的估计数据、系数、先验或随机种子；
- 不改变链概率、CI 中心/边界、Brier、可靠性、逐跳胜率或 oracle 结果；
- 不用确认结果重新选择模型，也不对整体低估作事后校准；
- 不删除 A003 或其他历史预承诺。

## 预期影响

历史概率和校准指标保持不变；JSON/CSV 会增加逐前缀不确定性字段和真正执行的首停字段，因此
`model_run.json` 与 ledger 的文件哈希会变化。A004 必须绑定这些新哈希。该变化属于执行与报告
语义修复，不是预测性能调优。
